## 3. 派工前要补的（P1）

### 3.1 酒馆人质节拍的命中规则没写

PLAN §8.3 规定：人质节拍中，只有打中匪徒的指定弱点才算解救。T04 只写了"酒馆误伤"。

需要在 T01 或 T04 中写明三种结果：

| 玩家操作 | 结果 |
|---|---|
| 打中匪徒头部（弱点） | 播 `A4_change_doors`，解救成功 |
| 打中女招待 | 播 `A4_scare`，扣 1 条命 |
| 打中匪徒身体 | **待定** |

建议：打中匪徒身体按打空处理，消耗弹药，并给出"瞄准头部"的提示。

### 3.2 终点与提前命中的规则冲突

`A4_change_doors` 的结尾是披肩匪徒推门举枪，此时试玩结束。PLAN §10.3 允许在 `kill_enter` 尾段提前命中下一个目标，玩家看到举枪的敌人会本能开枪。

需要二选一：

- **方案 A（建议）**：从他可见的那一帧起禁用交互，射击不扣弹药；冻结末帧，显示完成页。
- **方案 B**：允许击中他，但不播结局片段，只给一个"未完待续"的反馈。

### 3.3 有三个节拍的敌人开火几乎看不出来

方法：在每条 `threat` 中找 20×20 像素块的最大帧间变亮幅度。

| 片段 | 开火帧 | 时间 | 局部变亮幅度 | 画面表现 |
|---|---|---|---|---|
| `A1_threat_wagon` | 73 | 3.04 秒 | 149 | 明显的枪口闪光 |
| `A4_threat_porch` | 66 | 2.75 秒 | 164 | 明显的枪口闪光 |
| `A3_threat_store` | 71 | 2.96 秒 | 44 | 一般 |
| `A1_threat_barrels` | 68 | 2.83 秒 | 53 | 很弱 |
| `A2_threat_window` | 63 | 2.62 秒 | 25 | 只有一缕烟 |
| `A2_threat_roof` | 63 | 2.62 秒 | 20 | 只有一缕烟 |

A2 的两个远处目标超时扣命时，玩家很可能不知道自己被打了。

建议在 T05 中明确：

- 引擎在 `fires_at` 帧叠加枪口火光特效，并播放敌人枪声（PLAN §15 已要求敌人枪声由引擎播放）。
- 同时给出受伤反馈：红色暗角、震屏、生命图标变化。

### 3.4 反应窗口没给数值，也没说怎么调

六个节拍的开火都在 2.6–3.0 秒，"教学约 3 秒"与后面的节拍没有区别。PLAN §24.3 要求第 1 章的窗口从 3.0 秒逐步降到 1.6 秒。按 PLAN §4.3 的变速上限 1.25 倍，只能压到约 2.1 秒。

建议在 T01 中为每个节拍规定：

1. 普通难度下的目标窗口时长。
2. 实现方式：从 `threat` 中途起播，或者变速，或者两者结合。
3. 上表的开火帧作为 `fires_at` 候选值，由 T03 在成片上确认。

### 3.5 T03 与 T04 之间的标注格式没定义

T03 和 T04 会派给不同的 agent，标注格式要在 T01 中先定下来。可选格式有三种：每帧包围盒、多边形、PLAN §12.2 的 1/8 分辨率 ID 掩码（RLE 压缩）。

T03 也没有写用什么工具标注，而本机还没有安装 SAM2。

实测数据显示标注量可以大幅缩小：

| 片段 | 开火前相对首帧的最大偏差 | 建议的标注方式 |
|---|---|---|
| `A1_threat_barrels` | 1.6 | 开火前用一个多边形 |
| `A2_threat_window` | 2.0 | 开火前用一个多边形 |
| `A2_threat_roof` | 1.7 | 开火前用一个多边形 |
| `A1_threat_wagon`、`A3_threat_store`、`A4_threat_porch` | 开火后偏差 8–18 | 开火前用一个多边形；开火后用关键帧插值 |
| `enter` 尾段、`cross_clerk`、`change` 尾段 | 人物在运动 | 逐帧或关键帧插值 |

（偏差为 320×180 灰度图的平均绝对差，0–255 刻度；片内相邻帧差的中位数约 0.15。）

### 3.6 `A1_threat_wagon` 内部有重复拼接

这条片段由源帧 `[0,6) + [69,86)×3 + [74,89) + [89,124)` 拼成，用循环一段等待动作把窗口拉长。

| 输出帧 | 源帧跳变 | 帧间差 |
|---|---|---|
| 6 | 5 → 69 | 1.82 |
| 23 | 85 → 69 | 1.25 |
| 40 | 85 → 69 | 1.22 |
| 57 | 85 → 74 | 0.50 |

片内相邻帧差的中位数是 0.15，前三个拼接点是它的 8–12 倍。这是教学节拍，玩家看得最仔细，而且超时后会循环重播。

建议在 T03 或 T05 的验收中加一条人工检查：看得出跳动的话，重新生成这条片段，或在拼接点做淡化。

## 4. 建议补充的（P2）

### 4.1 片段衔接处有轻微的纹理跳变

| 位置 | 帧差 |
|---|---|
| 片内相邻帧（中位数） | 0.15 |
| 线性衔接（上一段末帧 → 下一段首帧） | 1.8–3.3 |
| `threat` 循环（末帧 → 首帧） | 1.3–1.6 |

在 640×360 RGB 上抽查了 4 处衔接：整体色彩偏移很小，RGB 平均不到 2 个色阶；差别来自细节纹理重画，5–9% 的像素差超过 12。

PLAN v0.5 规定同锚帧的线性片段直接衔接。建议：

- T02 的验收增加一条：在电视尺寸下目视检查衔接和循环点。
- 播放器保留一个可配置的 1–2 帧淡化，线性衔接也可以启用。

### 4.2 钱袋的规则没定

T03 要求区分钱袋，但没有说打中钱袋算什么。建议：打中钱袋算命中敌人身体，不算弱点。**待需求方确认。**

### 4.3 开火后还能不能击杀，要写进 T04

PLAN §4.3 允许整个 `threat` 期间都能击杀，包括开火后的后坐阶段。T04 应写明：

- 开火之后、循环结束之前，敌人仍然可以被击杀。
- 每一轮循环的超时只结算一次。

### 4.4 T02 没规定工具链

本机有 CMake 和 Visual Studio 2022，没有 vcpkg 和 ninja。T02 应明确：

- SDL3 和 FFmpeg 的获取方式：vcpkg manifest 锁定 baseline，或者在 `third_party/` 放预编译动态库。
- FFmpeg 使用 LGPL 构建，不启用 GPL 组件。
- CMake 生成器和编译器版本。

否则几个 agent 会各自搭出不同的环境。

### 4.5 素材交接要单列一个 T00

`assets/` 总共 126MB，在 GitHub LFS 免费额度内。目前 `assets/` 没有被 git 跟踪，仓库里也没有 `.gitattributes`。

建议在 T01 之前增加 T00：

1. 建 `.gitattributes`，按 PLAN §19 配置 LFS 规则。
2. 用 LFS 提交 `assets/western/` 下的切片、关键帧和配音。
3. 在干净的 checkout 上验证素材齐全、哈希一致。

任务书目前只把它列为风险，没有指派负责的任务。

### 4.6 鼠标换弹的按键没写

窗口模式下，鼠标无法"枪口指向屏幕外"开枪。建议 T04 写明：鼠标用右键换弹；屏幕外开枪换弹留给 TVGun。

## 5. 小问题（P3）

1. **规范关键帧的目录**：清单哈希对应 `assets/western/kf/`（15/15 匹配），`kf_raw/` 一张都不匹配。T01 应写明规范关键帧取自 `kf/`。
2. **对白有两份**：片内音轨 6.58 秒，`assets/western/voice/A0_M_zh.wav` 6.08 秒。T05 应说明字幕按片内音轨定时，wav 在运行时不播放。
3. **借用的音轨**：`A0_mayor_leaves`、`A3_travel_saloon`、`A4_scare` 的音轨借自其他片段（清单中的 `audio_source` 字段）。T05 核对声音时要特别听这三条。
4. **TVGun 下的目标尺寸**：白边加暗带之后视频区域会缩小。T07 要复核 A2 窗口和屋顶这两个远处目标，是否仍然达到 PLAN §10.3 的最小尺寸。

## 7. 测量方法

可以按下面的方法复现：

- 帧差：用 ffmpeg 把成片缩放到 320×180 灰度，计算相邻帧或指定两帧的平均绝对差，刻度 0–255。
- 开火帧：把相邻帧差按 20×20 像素块求平均，取变亮幅度最大的块和帧。
- 衔接色差：取上一段末帧和下一段首帧，在 640×360 RGB 上计算平均偏移，以及差值超过 12 和 30 的像素比例。
