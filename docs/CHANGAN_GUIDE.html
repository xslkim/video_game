03 / 判定逻辑

一箭如何被判定

实际显示的画面、当时的可射击窗口与当帧区域共同决定结果。下面的绳结图使用正式视频和实际逐帧标注。

  1. ① 输入到达鼠标、触屏、手柄或 TVGun 输入，映射到游戏的 16:9 画面坐标。
  2. ② 找到所见帧按输入时刻取当时已经显示的帧。校验窗口、暂停状态和弹药。
  3. ③ 检查该帧的位置目标、护盾、百姓、投射物可能有各自独立的区域。精确区域优先处理。
  4. ④ 应用反馈与分支记录命中或失手，更新生命、弹药与得分，播放回应并决定下一阵。

街战用逐帧掩码

街景和敌人使用统一画布尺寸。敌人变远、变小或移动时，命中跟着当帧掩码走。简单、普通提供距离辅助，百姓保护区域仍按自身边界处理。打到敌人会触发受击或净化，青火飞出后可用拦截窗口处理。

整幅战斗用逐帧多边形

曲江船只、塔上的墨鸦和宫门灯链连同背景一起播放。每个有效目标都有随成片变化的轮廓与窗口。普通战斗中，射空或打到护盾可以消耗一箭并继续当前窗口。已累计的多击命中会影响本阵是否结束。

八箭符匣与雷符

每匣 8 箭，可手动更换。换匣期间普通攻击锁定，场景与效果继续。命中累计雷符，打空会消耗部分能量，受伤或误伤会中断连击。蓄满后按雷符键，对规则允许的当前目标暴露弱点或造成至多两段伤害，效果由窗口决定。

剧情一箭与剧情选择

剧情射击使用普通射击键，按专门窗口计时，不消耗常规符箭。命中、选错、打空或超时可以接不同视频。救阿萤、护裴照和终章一箭的短期结果不同，之后回到各自的主线路径。镜廊允许互换左右顺序。

存档和失败重试

完成阶段后写下下一段、难度、符箭、生命、雷符进度和已得成绩。退出再继续时从尚未完成的段落开头进入。生命耗尽提供本段重试。已有通关存档可看总评，重新开始时清掉上一局进度。

分数与评级

常规净化分受命中时机和连击影响，多段命中有自己的分值，安全解救百姓另计奖励。章节结算和总评显示分数、命中、最高连击、受伤及净化。Windows 的 S 需命中率达到 90%、零受伤且有净化，A 需达到 75% 且受伤至多 2，B 需达到 50%，其余为 C。

04 / 运行架构

画面和规则如何协同

关卡表决定下一段。视频负责动作和场景，规则负责何时、何处可以响应输入，渲染器再把命中光效和界面叠上去。

关卡编排

标题与难度 → 当前章节 → 阶段 → 子镜头或目标窗口 → 分支回应 → 下一阶段。章节有独立成绩，走完尾声进入总评。

媒体与画面

剧情和大多数战斗以整幅镜头播放。两段朱雀街战斗把街景、带透明通道的角色动作和净化接片分开。播放层准备即将用到的镜头，渲染层按实际呈现的画面提交。

判定与数据

逐帧掩码或多边形与对应视频匹配。输入读取画面时机后返回结果，由关卡规则处理分支、箭数、生命、分数和续关快照。

光效与界面

由底向上依次是街景或整幅视频、可独立切换的街战动作层、画面反馈、准星与界面。命中火花和净化光在前景独立计时，视频切到回应段时仍可以完整播完。

混音与字幕

片内音轨、章节音乐、角色对白和射击等拟音按各自时机混合。换匣、拦截、失手和误伤有独立声音提示。对白音量、效果、配乐和字幕可分别控制。

离线与存储

为什么最后一只怪物出来时街景会停

朱雀街的街景只播放一次，播到最后一帧后保留这张画面，避免循环时路人、影子或灯景跳回原位。怪物和前景光效走各自的时钟，所以后段街景能静止，怪物依然可动、可命中。教学街景源片约 48 秒，三怪接力街景源片约 7.3 秒，两段有各自的起播点。

Android 的解码回退

现代 Android 优先播放 960 × 540 H.264。遇到解码错误或视频时钟停住，以同一镜头的离线帧页恢复，保留当前目标、已命中次数、生命和弹药。旧电视兼容路径使用同源帧页，交互每秒 24 帧、剧情每秒 12 帧。分阵的判定按源帧对齐。

TVGun 的显示与输入

游戏端显示外白内暗的光学边框，手机摄像头由四边定位屏幕，把瞄准点回传。开始、开火、换匣和雷符走局域网，重复射击包只计一次。失锁会暂停，重新瞄准后按 START 继续。

正式包的观察范围

Windows 三档均通关，已验证强退续关。Android 22、34、36 模拟器均通关，API 34 电视在这台电脑上的模拟切镜较慢。实体 TV 光枪的客厅精度、显示延迟和老芯片帧率仍需实机测量。
