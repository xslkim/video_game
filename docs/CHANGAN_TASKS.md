## T00 · 复现基线，约定两款游戏的入口

从 [西部试玩说明](PLAY_FIRST_MINUTE.md) 和 [西部 QA](FIRST_MINUTE_QA.md) 读取构建方式及已验证范围。检查工作区原有改动、LFS 素材是否已取回。在仓库根目录用 PowerShell 复现已有版本。

```powershell
python -X utf8 tools/player/check_opening.py
if ($LASTEXITCODE -ne 0) { throw 'Western asset validation failed' }
.\tools\player\build.ps1 -VcpkgRoot C:/vcpkg
$run = Start-Process -FilePath .\dist\DustCreek\DustCreek.exe -WorkingDirectory (Get-Location).Path -ArgumentList '--smoke','build/qa/western-baseline' -WindowStyle Hidden -Wait -PassThru
if ($run.ExitCode -ne 0) { throw "Western replay failed ($($run.ExitCode))" }
Get-Content -Encoding UTF8 build/qa/western-baseline/playthrough.json
```

构建脚本会运行 CTest。确认素材校验、`opening_rules` 和首分钟实际播放器均通过。留下命令、结果和环境。以上是西部现有入口，T03 负责实现长安入口与打包。长安装入自己的发布目录，保留西部的现有默认启动方式。开发期采用独立关卡数据和媒体清单，共享代码改动后重跑西部回归。

可直接复用的入口包括 [SDL 输入与显示帧记录](../apps/player/main.cpp)、[视频解码](../apps/player/media.cpp)、[混音](../apps/player/sound.cpp)、[TVGun 协议](../apps/player/tvgun.cpp)、[掩码工具](../tools/player/masks.py) 和 [现有规则测试](../tests/opening.cpp)。`main.cpp` 和 [安装规则](../CMakeLists.txt) 当前绑定西部路径，改造量要计入 T03。

## T01 · 冻结三节点素材与数据接口

在 `worlds/changan/` 建立第一条可校验的接力链，按总体方案 §10.4 落盘。一个节点代表一个可结算目标，一个素材 ID 指向一条定稿片。以下是生产、程序和测试共用的最小字段语义，序列化格式以实际加载器为准。

| 数据 | 必须表达的内容 |
|---|---|
| 成片 | 稳定 ID、相对路径、哈希、分辨率、帧率、实际帧数、首尾锚帧、与哈希绑定的掩码及事件 |
| 节点与分支 | 目标 ID、生命值、事件的前置条件、结果片 ID、下一节点或回归位置，链末进入 `purify_end` 后结束 |
| 交互区 | 片段内从 0 开始的显示帧，窗口一律左闭右开。区分目标、投射物、盾、保护区和背景，接力尾段可命中的帧绑定下一节点 ID |
| 攻击时序 | 发射帧 `launch_frame`、拦截窗口、抵达帧 `impact_frame`。可拦截攻击发射时只改变阶段，抵达且仍未拦截才结算伤害 |
| 复现信息 | 难度、节点访问次数、片段 ID 与实际显示帧、输入和结算、弹药 / 生命 / 连击 / 雷符能量、所走分支，输入与提交时间使用同一单调时钟 |

先为下面三个节点登记分支，再提交 H3 作业。

| 节点 | 定稿分支必须覆盖 |
|---|---|
| 横移灯笼妖 | 从威胁片的早、中、晚位置命中均能进入净化，尾段引出鬼火，定位可识别、可命中的首帧 |
| 火球鬼火 | 发射前净化，飞行中拦截后回到蓄力，拦截失败抵达后扣命一次，净化后转向狐火精英 |
| 多击狐火精英 | 非终结命中受击后返回当前节点并保留剩余生命值，终结命中进入链末净化，结束页可重开 |

每条边登记起点锚帧、落点锚帧、生效条件、复用或新生成的素材 ID。对 A1 预留诱饵启用/跳过、误伤后恢复，在对应章节补齐镜廊两种首选、剧情一枪成功/失手合流、各 Boss 阶段及链末。按唯一成片 ID 汇总生成数，失败候选和返修单独记录。

**验收**　自动检查可达节点、行进和返回出口、素材绑定、帧索引和非法窗口。加入一条损坏的引用、一条越界窗口作为反例，校验应指向具体节点或片段。成片尚在生产时可校验结构，T04 对所有实际文件重跑。

## T02 · 生成并标注三个真实节点

1. 用同一张上元夜街景母版确定三处出场位置、移动方向和光源。先制作灯笼妖横移的威胁片，拿早、中、晚三个真实显示帧对齐净化入口。检查命中前后主体位置、大小、轮廓和背景。先尝试约束轨迹，差异仍可见时按姿态补入口并更新账本。
2. 按 T01 的唯一素材清单逐条使用 H3 生成，保留候选号、锚帧、实际 GPU 用时及选用原因。制作火球发射、飞行、抵达和打断的完整动作，制作精英受击返回、最后一次净化和链末。生成的视频保持干净，准星、提示、字幕和符光在运行时叠加。
3. 在最终编码的 MP4 上标注逐帧掩码、首个可击帧、发射、拦截和抵达帧。分别导出转场头尾、晚命中和拦截末帧的叠图。场面移动时在实际显示坐标检查偏移。重剪或换片后重新核对哈希、事件与标注。

**交付**　定稿资产放 `assets/changan/`，运行时配置放 `worlds/changan/`。候选和中间产物留在工作目录，版本交接沿用项目 LFS 与用户的提交范围。单块 GPU 遵循方案 §16 的排队方式。记录总 GPU 分钟、候选数、选用数和每段返工原因，为 A1 排期提供实数。

## T03 · 接入播放器、状态机与实时反馈

- 在现有播放器建立长安入口，读取关卡声明的资源、尺寸和时序。按场景载入活动片、预热可能分支、淘汰离开场景的资源。测试切换场景和反复重开，分别记录进程内存、GPU 纹理、缓存帧数与切换提交延迟。音频与视频随同一游戏时间处理暂停、顿帧和恢复。
- 按已经呈现给玩家的帧判定。纯转场忽略射击，保留换匣。自下一目标首个可识别、可命中的帧起允许提前命中。接力尾段提前命中与进入下一节点后命中的结果应相同。每次命中、扣弹、奖励与攻击伤害只结算一次，切换分支后丢弃旧片段的延迟事件。
- A0 先做鼠标普通难度、符弩、换匣、必要的命中/拦截/受伤反馈、暂停与重开。雷符作用于当前节点，小妖净化、精英承受两次命中的伤害，自动净化后继目标保留为备选。A0 用满能量回放验证释放，普通游戏按难度充能。A1 验证命中加能、打空扣能与受伤清零。12 节点的自然命中数不足以充满时，另用一条可复现的长路线验证从零蓄满，保持普通路线原有耗弹与目标数。
- 接入输入回放、显示帧日志和开发叠图。将长安启动、构建、打包、校验及自动试玩命令写进实际项目说明并运行一次。保留鼠标菜单和游戏内的正常入口，自动回放能经过同一套输入、分支与渲染代码。

**验收**　T02 与 T03 汇合后，长安的独立目录可离线启动，在另一工作目录启动也能找到资源。再次运行西部素材检查、CTest 和原有鼠标试玩，共用输入或时钟若有改动，补跑西部 `--early` 与 `--recovery`。

## T04 · 验收 M0-A0

| 如何操作 | 怎样算通过 |
|---|---|
| 灯笼妖分别早、中、晚命中，分别从转场尾段和下一段首个显示帧命中 | 首个可击帧之前的纯转场输入不扣弹、不计失误。可击后同一目标仅结算一次。回看早中晚的前后帧，主体位置和镜头没有玩家能察觉的跳变 |
| 让火球发射，分别在拦截首帧、最后一帧、抵达时操作，再试完全不操作 | 发射时生命不减，窗口内成功阻止后续伤害，错过并抵达只扣一次。同轮循环、重复包和迟到输入均不造成重复扣命 |
| 对精英连续输入，在受击返回、顿帧或暂停中输入，最后完成链末 | 剩余生命、有效箭数和状态图一致，重开清空本轮状态，界面和音画能从暂停恢复。雷符测试覆盖精英剩余生命高于或不高于两次伤害 |
| 普通难度按自然接力完成并重复，另跑提前命中的路线 | 每次记录上一目标终结命中 T_hit、下一目标首个实际呈现的可击帧 T_open、下一次有效射击 T_input。接力等待取 T_open−T_hit，玩家反应取 T_input−T_open。自然接力目标 1.2–1.8 秒，每条样本含顿帧且不超过 2 秒，提前开放更短时，另看目标是否容易辨认 |

**交给玩家**　给出可直接运行的包、启动方式、三个节点的顺序，以及“晚打灯妖、放出并拦住火球、连续命中精英”的试玩路线。记录玩家观察、问题节点与帧号、结论和返修项。自动试玩可证明规则正确，**A0 通过需要需求方实际试玩确认衔接和手感**。若接缝明显，先按 §10.2 尝试局部修复或短净化方案，复测仍未达到接力要求时，按 §10.9 交故事优先小样给玩家复评，再决定批量生产方式。

## T05 · M0-A1，扩成 40–50 秒的完整遭遇

沿用 A0 的场景、定稿片与数据合同，扩至约 12 个节点。加入一次实际需要的换匣、一名诱饵百姓、火球拦截与一个精英。启用完整打击反馈、声音和三档难度。普通路线从满匣开始，安排一次合理换匣，记录有效耗弹，把打空或故意多射另列。按 §7 验普通预警 1.0–1.8 秒、跨场不可操作片段最多 2 秒，记录各难度的实际帧窗口及预警、发射、拦截和抵达次数。测试诱饵启用/跳过后的视觉衔接、误伤恢复和失败重试、雷符释放与链末边界。

**验收**　桌面发布包、真实播放器输入回放、分支覆盖表、每条自然接力时间与性能记录、更新后的资产与 GPU 工时账。玩家确认约 12 节点的节奏和画面质量后放行第一章。每章六次换匣、十五次预警留给整章弹量和攻击机会表评估。

## T06 · M0-B 与 M0-C，美术和声音选型

- **人物与妖怪。** 依 §9、§13 制作四人定妆、阿萤与沈砚各五个短镜头及五种精英妖设定图。把同角色的远近景、不同光照与定妆图放在一起，记录需求方选定的版本、稳定特征及需要重做的镜头。
- **声音。** 依 §11、§16 对比阿萤和玄烛各五句台词，交一段口型样片、两首音乐样曲及十种打击音效样本。用同句和相同音量试听。记录来源、模型、声音版本、对齐和选型。外部服务需要账号时先做可用的本地样本，单列尚待比较的候选。
- **交接。** 记录正式采用的资产 ID 与生成条件，将已选音效回接 A1 复验。B/C 的样片可并行，人物与声音的最终选型分别由需求方确认。

## 每个会话的交接

在交接消息或该里程碑的 QA 记录写明任务编号、仓库版本、已改路径、可运行入口、实际运行过的命令与结果、证据位置、人工试玩结论和下一项依赖。保留已有基线，缺素材时定位到片段 ID，规则问题定位到节点、输入和显示帧。这样下一次会话可以从同一个可复现问题或已验收里程碑接手。
