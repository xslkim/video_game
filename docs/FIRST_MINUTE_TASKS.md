| 28.875–41.5 秒 · 旅馆与屋顶 | `A2_enter_window` → `A2_threat_window` → `A2_change_roof` → `A2_threat_roof` → `A2_exit_roof` → `A2_travel_store` | 依次识别窗口和屋顶的角色；超时可在本节拍重试 |

## 3. 可单独派发的任务

每次领取一个任务编号。下列目录是建议的实现位置，可随项目已有结构调整。各任务提交时写明变更文件、可复制的构建或检查命令、实测结果，以及需要下游使用的接口或数据文件。

### T00 · 固定可交接的素材版本

用 Git LFS 管理西部关键帧、成片和配音，在全新本地 clone 中比对 26 个 MP4 和 15 张规范帧的 SHA-256。规范帧目录取 `assets/western/kf/`。本地素材提交为 `b62a9a3`，全新 clone 的 41 项校验通过。远端交付另需验证远端 LFS 存储及实际配额。

### T01 · 固定素材版本，建立首分钟关卡数据

**依赖**　T00 的同版本素材。**交付**　[关卡数据](../worlds/western/opening/level.json)及[校验命令](../tools/player/check_opening.py)。

- 从生产清单引用片名、哈希、帧数和声音。单独保存玩法数据，包含节拍、入口、成功、超时、误伤、生命归零和完成出口。未标注事件显式标记为待填，开发模式可以报告，发行检查必须报错。
- 统一约定片段局部帧从 0 开始，区间采用左闭右开。定义 `shootable_from`、`fires_at`、可交互实体 ID、标注版本和所绑定的成片 SHA-256。`preview_route.frames` 是顺播选取的长度，`preview_cut_before` 是编辑参考，两者均不能直接填入玩法事件。
- **验收**　一个命令核对 26 个文件和 15 张规范帧、遍历正常路线和两个条件分支。缺文件、哈希变化、帧号越界、出口无定义时，返回失败并指出片名。干净工作区能说明从哪里取得同版本素材。

### T02 · 建立 Windows 播放器，打通切片播放

**依赖**　可与 T01 同时开始。**交付**　CMake 工程、`apps/player`、首次构建和启动命令。

- 沿用 C++20、SDL3、OpenGL 3.3、动态链接 FFmpeg。第一版直接读取本地 MP4；视频按音频时钟呈现，输入与界面独立更新。输出可查询当前显示的片名、局部帧号和显示时间。
- 先播 A1 入场、对峙、切到木桶，再验证 A0 对白前后切片。实现下一片预热、跳片时清理旧音画、暂停/失焦冻结、恢复和重开。处理两种采样率与声道布局。
- **验收**　新启动的进程可按说明播放 A1，调试操作能在对峙中途切到木桶。重复切换后没有黑帧、旧对白、越来越大的音画偏移或解码器泄漏。日志区分输入时刻、显示帧和分支首帧。
- Windows x64 使用 VS 2022、CMake 的 VS 生成器和仓库的 vcpkg manifest。本机已有 `C:/vcpkg/vcpkg.exe`。FFmpeg 采用动态库及解码所需特性。线性衔接和循环可对比直切、1 帧及 2 帧淡化。电视实测单列观察纹理细跳。

### T03 · 按最终视频标注可交互帧

**依赖**　T01 的帧号和文件接口。**交付**　A1 的首批标注先供 T04 使用，再补 A2–A4；附开发用逐帧叠加检查方式。

- 给六条 `threat` 标出首次超时事件；给相应 `enter` 和切换到下一角色的片尾标出可交互起点。T01 中的六个节拍均须有可审核的局部帧号。摆门终点只触发完成。
- 在最终 720p 画面标注可见角色、受保护角色、遮挡及游戏要求的角色子区域。区分店员、钱袋、木桶、栏杆和人物。重点检查店员进出画面、窗口边缘、酒馆两人轮廓交界。若目标过小或动作提示读不清，登记片名、帧号和截图，再决定调时间还是返修镜头。
- **验收**　对交互区间逐帧查覆盖，用代表帧叠图核对边界。每个节拍给出有效点、空白点、遮挡点的回放样例；另给店员、人质及相邻角色的样例。更换成片后旧标注能被校验拦下。
- 当前接口由 `level.json` 和同名 `.mask` 组成。`opens` 对应首个可交互帧（含），`expires` 对应首个超时事件帧（不含于有效窗口），`start` 为对峙起播帧号。DCM1 掩码依次存 4 字节签名、32 字节成片 SHA-256、uint16 帧数；每帧存 uint16 段数和若干 uint16 三元组 `(y, x0, x1)`，均为小端序。掩码画布为 640×360，区间为 `[x0,x1)`，在最终视频坐标上除以二查询。空帧、遮挡及背景均无有效段。酒馆的独立标记使用关卡内给出的 720p 坐标。
- 马车对峙检查第 6、23、40、57 帧内部拼接点，并看超时循环；内部拼接与切片间淡化分别验收。若电视上可见明显跳动，再返修具体镜头并重新绑定哈希。

**普通难度的首分钟窗口。** 以最终视频局部帧计数，起止帧之间按 24fps 原速播放。重试时延长 25%。优先使用等待段中途起播，第一章后段的 1.6 秒目标留给后续内容。

| 节拍 | 起播帧 | 超时帧 | 有效时长 |
|---|---:|---:|---:|
| 马车 | 1 | 73 | 3.00 秒 |
| 木桶 | 2 | 68 | 2.75 秒 |
| 窗口 | 1 | 63 | 2.58 秒 |
| 屋顶 | 6 | 63 | 2.38 秒 |
| 杂货店 | 14 | 68 | 2.25 秒 |
| 酒馆 | 18 | 66 | 2.00 秒 |

评审稿对杂货店给出的 71 是亮度峰值。最终文件第 68 帧已出现明显闪光，作为该段超时事件。

### T04 · 实现游戏规则，先交一个能玩的 A1

**依赖**　T01、T02 和 T03 的 A1 标注。**交付**　状态机、鼠标输入、显示帧查询，以及可独立运行的规则测试。A1 通过后用完整标注接通 A2–A4。

- 按玩家操作选择视频边。有效交互立即跳结果片；打空消耗弹药，当前片继续；超时结算一次，存活时重播当前对峙。支持入场尾段提前完成、上一目标退出时下一目标的有效输入、同轮结算去重。转场等待期间不推进交互节拍。
- 实现普通难度、3 命、6 发、0.5 秒换弹、教学保护、重试窗口、分数与连击。店员穿行内误伤最多扣一次，完全忍住可得奖励。酒馆误伤、失败、从当前站位续关和从开头重玩各有独立出口。具体数值及结算口径沿用总方案 §10.3–10.4。
- 将鼠标位置映射到**玩家看到的那一帧**，记录当时的视口变换。测窗口缩放、留黑、暂停、连续点击及上一轮迟到的输入。用正常输入路径完成回放。
- **验收**　A1 可用鼠标实际打通；同一段可分别触发成功、打空、超时和换弹。随后从 A0 走通六个节拍，D01 和受惊分支均可由实际规则触发。开火前一帧与开火帧的结算顺序可重复，单次事件只扣一次生命或弹药。
- 按总方案 §4.3，超时帧起关闭本轮交互，整轮只扣一次。后坐时仍可完成同一目标的评审建议与当前方案相冲突。鼠标右键换弹，杂货店钱袋计作普通有效交互。摆门一段全程关闭射击和扣弹，末帧冻结后显示完成页。
- 当前酒馆版本采用独立金色解救星徽、红色保护标记。选择星徽解救成功；误选保护标记扣命并依生命数进入受惊或失败；其余位置按落空处理并显示星徽提示。这项街机交互取代初稿的角色弱点规则。

### T05 · 补齐玩家反馈、字幕和完整试玩流程

**依赖**　T02、T04 的状态与事件接口。**交付**　中文开始、暂停、结束和失败页，运行时 HUD、字幕表和音频反馈。

- 显示生命、弹药、换弹、当前反馈和结束统计；店员场景让玩家能理解“不要开枪”，酒馆能区分成功、误伤和超时。开发标注叠层仅在调试模式开启。
- 镇长台词使用“副警长，黑帽帮在抢银行！快去主街，镇上的人就靠你了。”对照实际声音给字幕分句定时。统一处理切片环境音、对白和短音效；已有对白及片内动作声逐处核对，避免叠播。暂停、跳过与重开同步清理声音和字幕。
- **验收**　首次玩家可凭画面和中文提示完成操作。用完弹药、误伤、失去最后一命、续关、完成后重开均有可见回应。原始视频校验哈希保持一致。
- 超时事件同步触发短音效、画面边缘受伤提示、短暂震动及生命变化。检查木桶、窗口和屋顶在电视上是否读得清。字幕以片内 158 帧的对白段定时，6.08 秒的独立 WAV 留作制作素材。换场试听应包含借用环境声的 `A0_mayor_leaves`、`A3_travel_saloon`、`A4_scare`。

### T06 · 交付 G1，打包并回归 Windows 鼠标版

**依赖**　T01–T05。**交付**　可直接运行的 Windows 包、README、复现输入和带设备信息的测试结果。

- 包含运行程序、动态库、关卡、26 条切片或等价的逐站位包、标注、中文字体及声音。若做逐站打包，用索引验证片内帧号和音频时长。移到另一目录后启动，覆盖中文和空格路径，断开 WSL、模型服务和开发目录后再跑一遍。
- **必测**　完整成功路线、跳过序幕、教学超时、空仓换弹、误伤店员、酒馆受惊后恢复、最后一命失败、续关、到达摆门后重开。记录输入，在 30/60Hz 显示更新下比较路径、生命和分数。报告参考路线时长及玩家最早、较晚完成时的实测时长。
- **性能证据**　分别记录输入到画面反馈、到分支首帧的 P50/P95，标明机器、样本量和最差片名。以总方案 §8.1 的下一次画面提交反馈、100ms 内出现分支首帧为目标。把超标项列入缺陷，区分桌面软件计时和真实电视端到端测量。
- **验收**　用发行包完成上述回归；交付启动命令、版本及已知问题。仅播放 60 秒预览的程序无法通过这些用例。

### T07 · 交付 G2，接 TVGun 并完成线下试玩

**依赖**　输入接口随 T04 冻结即可开始适配；最终使用 G1 的同版内容。**交付**　TVGun 输入适配、协议回放测试、连接说明、手机与显示设备的实测记录。

- 本机可只读参考 `D:/tvgun/android/src/com/tvgun/gun/GunProtocol.java`、`D:/tvgun/gunforge/framework/core/gun_input.gd` 和 `screen_frame.gd`。按总方案 §14 接现有手机游戏模式，验证发现、连接、定位框、触发、换弹、失锁与重连。保持同一关卡和规则入口。
- **验收**　先用协议回放检查重复包、乱序和失锁后的旧输入，再用手机与实际显示器或电视跑通成功、失败、换弹和暂停恢复。记录设备、显示模式、可读性和端到端延迟。设备暂缺时交协议测试结果，将 G2 标为“待真机”，G1 可独立交付。
- 在白框、暗带、电视过扫描及实际观看距离下，复核 A2 两个远景角色的显示尺寸与可辨认性，并记录马车教学片拼接点及循环观感。
